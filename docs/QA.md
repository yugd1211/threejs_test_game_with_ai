# QA와 개선 기록

검증 환경: 2026-10-06, Node.js 24.19.0, npm 11.9.0, 시스템 Chromium 151, Playwright. 브라우저 검증은 실제 WebGL을 SwiftShader 소프트웨어 렌더러로 실행했다.

## v2 — 10레벨과 입체 충돌

사용자 요청에 따라 이전 하드를 새 Easy로 재분류하고, 높낮이·승강 발판이 있는 10개 코스로 확장했다.

- 레벨 데이터: 고정 상승·하강, 수직 리프트, 반대 위상 리프트, 좌우·상하 복합 이동, 후반 좁은 발판.
- 렌더링과 물리가 같은 두께(1.5)의 고체 발판을 사용한다.
- 캐릭터의 폭과 키를 포함한 연속 충돌 검사: 양쪽 x/z 옆면, 아랫면, 빠른 낙하, 가장자리 이동, 이동하는 벽, 내려오는 발판의 아랫면.
- 리프트에 서서 상승·하강하는 동안 지지가 유지되고, 점프로 이탈할 수 있으며, 일시정지하면 발판도 정지.
- 높은 발판의 옆면에 계속 걸어도 관통·착지·체크포인트 활성화가 일어나지 않는 회귀 테스트.
- 10개 코스 모두 실제 입력만 주는 물리 시뮬레이션으로 완주. 순간이동·강제 승리 없음.
- 17개 크리스털 기록 저장 및 코스별 수량 초과 거부 테스트. 이전 v1 기록은 삭제하지 않고 새 v2 기록과 분리.
- 단위/시뮬레이션 테스트 **38개 통과**.
- 프로덕션 빌드·포맷 검사 통과. 배포용 페이지의 10개 코스 표시·시작·일시정지, 브라우저 오류 0개, 개발용 상태 API 미노출 확인.
- 모바일 가로 넘침 없음. 최신 화면: [데스크톱](screenshots/desktop.png), [모바일](screenshots/mobile.png), [승강 코스](screenshots/vertical-course.png).
- 브라우저 테스트 **12개 통과 (5.3분)**: 10개 코스 완주 테스트와 데스크톱·모바일 조작 테스트.
- 브라우저 검증은 코스마다 시작 → 키보드 완주 → 동적 수량 확인 → 다음 코스 이동 → 새로고침 후 기록 유지까지 수행한다.

아래는 초기 버전 개발 때의 기록이다. 현재 코스 구성은 README의 10개 레벨 표를 따른다.

## 반복 1 — 게임 규칙과 데스크톱

- 점프·착지·대각 속도·코요테 타임·입력 버퍼·체크포인트·이동 발판·회전 장애물·완주 조건을 독립적으로 검증.
- 시작, 도움말, 이동·점프, 일시정지/타이머 정지, 낙하 복귀, 재시작, 소리/품질 전환, 코스 변경, 기록 화면을 실제 Chromium 입력으로 확인.
- 초기 데스크톱 캡처를 검토한 뒤 조명 노출과 환경광을 낮춰 발판과 캐릭터를 구분하기 쉽게 조정.
- Three.js 최신 버전에서 제거된 PCFSoftShadowMap 대신 PCFShadowMap 사용.
- 런타임 Google Fonts 요청을 제거하고 npm 폰트 패키지를 로컬 번들로 전환.

## 반복 2 — 완주와 모바일

- 읽기 전용 개발 상태를 관찰하면서 **실제 키보드 입력만으로 세 코스를 각각 완주**. 순간이동, 좌표 변경, 강제 승리 없이 검증.
- 모든 코스 기록 저장 후 새로고침하고 세 기록이 남아 있는지 확인.
- 모바일 390×844 레이아웃에서 가로 넘침이 없는지 확인.
- 초기 합성 pointer 이벤트는 실제 활성 포인터가 없어 브라우저의 setPointerCapture가 거부했다. Chromium CDP의 실제 터치 입력으로 테스트를 변경.
- 소프트웨어 렌더링 환경에서 터치 해제 처리 지연으로 오래 전진한 테스트 캐릭터가 발판 밖으로 이동했다. 점프 동작을 입력 유지 중 관찰하고, 이동과 분리해 검증하도록 테스트를 수정. 이 실패를 제품 점프 버그 수정으로 보고하지 않는다.
- 모바일에서 시작 버튼을 누르면 게임 화면으로 즉시 스크롤하도록 개선.
- 일시정지/완주 화면에 접근성 이름을 부여하고, Tab 포커스가 해당 화면의 버튼 사이에 머물도록 개선.
- 실제 기기의 다중 터치·프레임률·발열 측정은 아직 하지 않았다.

## 반복 3 — 재설치와 배포 빌드

- 잠금 파일 기반 `npm ci --cache /workspace/.npm-cache` 재설치 성공.
- 실행 중인 Vite가 재설치 전 캐시 경로를 유지해 개발 의존성 요청에서 HTTP 504 발생. 앱 실행 코드 문제가 아닌 개발 서버의 오래된 캐시 참조로 확인.
- 이 작업에서 시작한 개발 서버만 종료하고 새 서버로 재검증. 앞으로의 재설치 절차에 개발 서버 종료/재시작을 기록.
- 배포용 서버 HTTP 200, 캔버스 렌더링, 시작·점프·일시정지 동작 확인.
- 배포용 페이지에서 브라우저 pageerror 0개, 외부 네트워크 요청 0개 확인.
- 배포용 `?qa=1`에서도 테스트 상태 API가 존재하지 않음을 확인.

## 남은 한계

- CrazyGames, Poki, Roblox 차트는 프록시 차단 때문에 내용을 검증하지 못했다. 현재 인기 순위에 대한 주장은 없다. 도메인 허용 설정을 적용한 후 재조사가 필요하다.
- 실제 사용자 인터뷰·플레이테스트, iOS/Android 실기기, Safari/Firefox 검증은 미실행.
- Three.js 공통 렌더링 청크는 약 540kB(전송 gzip 약 134kB)로 Vite의 기본 500kB 청크 경고가 남는다. 앱 코드를 별도 청크로 나눴으며 빌드는 성공한다. 실기기 성능 측정은 별도 필요하다.
- 최고 기록은 이 브라우저에만 저장된다. 온라인 순위표·동기화는 없다.
- 환경 설정 초안은 저장했지만 게시 및 새 환경 복원은 사용자 환경 설정 흐름에서 진행해야 한다.
