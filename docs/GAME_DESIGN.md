# SKYHOP — 게임 기획과 조사 기록

## 조사 범위와 근거의 한계

검증되지 않은 인기 숫자·이용자 수·리뷰를 UI에 넣지 않는다. 기존 게임의 브랜드, 맵, 에셋도 복제하지 않는다.

## 선택한 경험

**작은 점프, 커다란 모험.** 차분한 떠 있는 정원에서 출발해 크리스털을 수집하고 마지막 포털에 도착하는 3D 파쿠르. 자동 추적 카메라로 이동과 점프에 집중하고, 실패하면 가장 최근의 체크포인트에서 즉시 다시 시작한다.

- 대상: 설치·회원가입 없이 브라우저에서 잠깐 플레이하려는 사용자
- 핵심 루프: 경로 파악 → 가장자리로 이동 → 점프 → 수집/체크포인트 → 완주 → 기록 재도전
- 성공 조건: 마지막 섬의 포털 중심 도착. 크리스털 수집은 선택 목표(코스별 7–17개).
- 재도전: 시간 제한과 목숨 제한 없음. 낙하 횟수 표시, 수집 진행 유지.
- 로컬 기록: 코스별 가장 빠른 완주 기록과 해당 플레이의 크리스털·재도전 횟수.
- 시간: 실제 플레이 시간만 집계. 일시정지·탭 전환 시 중단.

## v2: 높낮이가 있는 10개 코스

사용자 피드백: 초기 세 코스가 너무 쉽고, 높낮이 변화가 작으며, 발판의 옆면을 통과한다.

- 이전 Hard Moonlight Run의 배치를 유지하고 레벨 1 / Easy로 재분류.
- 총 10개 코스, 9개 발판에서 최대 19개 발판까지 증가.
- 후반 일반 발판 폭은 1.65까지 감소. 체크포인트와 회전 장애물은 충분한 착지 면적 유지.
- 고정 높낮이 차이: 상승 계단, 1.5m 안팎의 높은 도약, 1.8–2m 하강 후 재상승.
- 동적 높낮이: `platformY`가 시간에 따라 변하는 승강 발판, 반대 위상 승강, 좌우·상하 복합 이동.
- 최대 점프 높이는 기존 약 2.05m 유지. 일부 리프트는 낮아지는 시점에 뛰거나 탑승 후 높아질 때 다음 발판으로 이동해야 한다.
- 코스별 크리스털 7–17개, 체크포인트 2개. UI·기록·완주 화면은 코스 데이터에서 수량 계산.
- 새로운 물리와 난이도의 기록은 `skyhop-records-v2`로 분리. 기존 저장 값은 삭제하지 않는다.

코스 순서와 기믹은 [README](../README.md)의 10개 레벨 표를 따른다. 모든 레벨은 처음부터 선택 가능하다.

## 입체 충돌 계약

- 플레이어: 수평 반폭 0.28, 키 1.6의 AABB. 위치의 y는 발바닥 기준.
- 발판: 화면의 본체와 동일한 두께 1.5의 고체 상자.
- 이동 경로를 연속 검사해 빠른 낙하에서도 윗면을 관통하지 않는다.
- 옆면에서는 해당 방향 이동이 막히고 나머지 방향으로 미끄러질 수 있다. 옆면 접촉을 착지로 취급하지 않는다.
- 아랫면에서는 머리가 막히고 상승 속도가 0이 된다.
- 발판과 플레이어의 상대 이동을 검사하므로 다가오는 이동 발판도 충돌한다.
- 탑승자는 발판의 상하·좌우 변위를 전달받으며 일시정지하면 발판도 멈춘다.
- 나무·깃발·크리스털 등 장식은 본체 충돌과 별개이다.

## 조작과 보정

- 데스크톱: WASD/방향키 이동, Space 점프, Esc/P 일시정지.
- 모바일: 누르고 있는 동안 이동하는 방향 버튼 + 별도 점프 버튼. 다중 터치 지원.
- 점프: 중력 22, 점프 속도 9.5, 이동 속도 6.4. 고정 120Hz 물리 업데이트.
- 조작 보정: 120ms 코요테 타임, 140ms 점프 버퍼, 대각 이동 속도 정규화.
- 복귀: 마지막 체크포인트에서 재시작, 짧은 무적 시간 제공.

## 시각·기술 방향

- Three.js 실제 3D 메시, 조명, 그림자, 원근 카메라, 플레이어 애니메이션.
- 직접 만든 절차적 로우폴리 섬·나무·구름·우주복 캐릭터·크리스털·포털.
- 차분한 남색 UI, 라임색 주요 행동, 코스별 테마 하늘색.
- Korean UI + English 게임 브랜딩. 모바일 세로 레이아웃.
- TypeScript + Vite. 서버, 계정, 외부 API, 비밀 키 불필요.
- Web Audio로 효과음 생성. 폰트는 npm 패키지에서 로컬 번들해 런타임 외부 요청 없음.

## 범위와 다음 검증

실시간 멀티플레이, 온라인 리더보드, 계정 동기화, 사용자 제작 맵, 수익화는 현재 범위에 포함하지 않는다. 최신 인기 검증과 실제 사용자 플레이 피드백은 별도 데이터가 필요하다. 현재 피드백 루프는 구현 → 자동/시각 QA → 수정 → 재검증이다.
